# Nebula Particle：开发需求与版本计划

版本：需求基线 0.5.0

日期：2026-11-12

状态：0.5.0 发行阶段；名称、安装升级、原生渲染与兼容性回归已完成，V1.0 尚在开发规划阶段

本文中的“必须”表示对应版本的验收要求，不表示功能已经实现。实现进度以源码、构建结果和 AE 实测记录为准。未经过 AE 实测的功能不得标记为完成。

当前实现、面板和验证边界见 [0.5.0 使用说明](验证版使用说明.md)。已接入外部亮度、颜色图、内部混合及 8/16 bpc；v0.2 增加分组和 ScriptUI 预设工作流，0.5.0 统一名称与发行安装。光流、GPU、烘焙和纵深尚未接入。项目原创源码按 GPL-3.0-only 开源，Adobe SDK 不随仓库分发。

## 1. 产品目标

做一个面向背景、文字、Logo、带 Alpha 的元素和运动序列帧的 AE 粒子装饰插件。用户指定素材并选择预设后，能迅速得到精致、连续、容易调整的效果。

优先优化以下体验：

1. 预设直接可用，弱化大量手动搭建步骤。
2. 颗粒细致、颜色丰富、闪耀有节奏，默认光晕克制。
3. 能持续发射，能够给画面内容中的运动主体添加拖尾。
4. 主面板参数少；精细控制保留在高级设置中。
5. 快速预览、可靠缓存、可烘焙；性能用实测结果评价。
6. 开发期间能够快速更新资源和兼容的绘制代码，并方便重启验证原生插件更新。

Particular、Dust Transition、C4D 克隆和 X-Particles 是能力与视觉参考。目标是覆盖本产品的常用装饰工作流，不以复刻这些产品的全部功能为验收标准。克隆实例不是第一版重点。

## 2. 已确定的需求与边界

| 编号 | 已确定需求 | 说明 |
| --- | --- | --- |
| R01 | 默认二维 | 插件默认作为普通二维效果使用，不自动引入纵深或摄像机依赖。 |
| R02 | 纵深显式开启 | 开启“纵深”后，才启用空间位置、AE 摄像机、朝向及景深相关能力。 |

| R04 | 多种发射依据 | 支持素材 Alpha、素材亮度、外部图层亮度。外部亮度图层可以是 3D 渲染输出的独立通道。 |
| R05 | 来源分工独立 | 发射遮罩、颜色来源、运动分析来源可以分别指定；默认尽量复用输入素材。 |
| R06 | 贴图影响颜色 | 第一优先是出生时取色并保留；沿途染色与贴图调色盘保留在规划内。 |
| R07 | 精致颗粒 | 细尘、清晰亮点、少量星芒和短光丝；控制尺寸层次、透明度、颜色与内部混合，不能依赖重光晕掩盖细节。 |
| R08 | 动画分开控制 | 出现、存活期间闪烁、消失是三个独立过程。关闭闪烁不影响出现与消失动画。 |
| R09 | 初速与阻尼 | 射出的粒子具有可控初速；阻尼使粒子逐渐减速。阻尼必须放在高级设置，不出现在初次展开的主面板。 |
| R10 | 画面内容拖尾 | 主体可以在序列帧像素中运动，不依赖 AE 图层的位置关键帧。 |
| R11 | 运动继承 | 可通过相邻帧光流估计运动，为新粒子赋予惯性；继承量可调。 |
| R12 | 丰富预设 | 随插件提供可直接使用的预设；以使用目的分类，并提供可辨认的预览。 |
| R13 | 缓存与烘焙 | 能复用运动分析和模拟结果，支持把昂贵的结果烘焙成图像，避免反复计算。 |
| R14 | 两种景深工作流 | 默认纵深景深由插件依据 AE 摄像机参数完成；外部 Crossphere Bokeh 工作流使用清晰颜色图与配套深度图。 |
| R15 | 不采用深度分组输出 | 不要求用户自行划分近、中、远粒子组来适配 Bokeh。复杂叠加优先使用插件内部景深。 |
| R16 | 克隆是后续高级能力 | 图层、预合成、文字等作为实例外观与排列的能力保留，但不能增加第一版主面板负担。 |
| R17 | 快速开发迭代 | 资源与兼容的外置 GPU 代码支持重新加载；原生主体变更保留构建、安装、重启测试流程。 |

## 3. 版本划分

### 3.1 v0.1：首个可在 AE 中加载的验证版

这是原生验证基线，目的是建立真实 AE 工作流和可比较的基准。它不等同于第一版产品已经完成。

最小验收范围：

- 原生效果插件可以在目标 AE 中识别、添加、保存工程和再次打开。
- 二维粒子生成与渲染，优先建立 CPU 参考路径。
- 输入素材的 Alpha 或亮度驱动持续发射；移动序列帧内容能够留下基本粒子拖尾。
- 出生颜色采样；原始元素可保留显示。
- 粒子数量、大小、寿命、初速及方向可以调整。
- 出现与消失动画可控；提供基本连续闪烁，不逐帧重新随机。
- 高级组中的阻尼实际影响粒子运动，并且与帧率无关。
- 弱光晕或无光晕的清晰颗粒；先做少量用于验证的预设。
- 固定随机种子下，同一帧重复渲染、跳帧访问、前后拖动时间线应得到一致结果。
- 给出构建、安装、运行与限制说明。

v0.1 允许的明确限制：

- 可以先只完成 8 bpc 渲染路径；在未实现前，不声明支持 16/32 bpc 或 HDR。
- 可以先以 CPU 验证正确性；不宣传 GPU 加速或超过 Particular 的速度。
- 光流、正式烘焙面板、纵深/景深、完整预设库可以尚未接入，但需要在版本记录中明确列为未实现。
- 外部图层输入、边缘提取、内部混合方式等按实际实现列出，不能以参数占位代替可用功能。

### 3.2 v0.2：参数分组与预设工作流

本阶段不增加 GPU 或光流能力，重点是让现有粒子更容易使用和复用：

- 效果控件顶层只保留 Preset、Density、Size、Lifetime。
- Sources、Appearance、Animation、Advanced 默认折叠；Advanced 下分 Motion、Timing、Development。
- 阻尼始终位于 Advanced → Motion，不提升到顶层。
- ScriptUI 面板提供 6 个内置起点、“我的预设”、命名保存、应用和刷新。
- 用户预设保存视觉与运动数值，不携带来源图层连接、发射通道、种子或发射时序。
- 同名保存自动另存；应用前检查所有目标参数，存在关键帧或表达式时整体拒绝，避免部分覆盖。
- 保持 v0.1 已保存工程的参数 ID、数值与图层连接兼容。

原生渲染、旧工程和预设数据的回归结果已记录；窗口菜单发现与实际交互结果分开记录，不能用脚本库测试替代全部 UI 验收。

### 3.3 0.5.0：名称统一与可安装发行

此版本将对外名称统一为 Nebula Particle，提供无需 SDK 的 macOS arm64 用户级安装包，并发布完整源码标签与许可证。它是当前功能集的正常发行版本，不表示 V1.0 路线已经完成。

为保留旧工程，内部效果匹配名与已有参数磁盘 ID 不变。旧名称资源和用户预设可继续读取，新保存写入 Nebula Particle 目录；安装器备份移走旧名插件与面板，避免重复注册，但不删除旧用户数据。

0.5.0 已完成重命名、旧名安装升级、旧工程与用户预设兼容、实际宿主渲染回归。发行归档内容在打包阶段单独校验；验证记录与源码标签对应，不能只改版本号后沿用历史结论。

### 3.4 V1.0：第一版二维粒子产品的验收目标

第一版聚焦二维装饰与运动素材拖尾，完成以下功能后才称为 V1.0：

| 模块 | V1.0 必须完成 |
| --- | --- |
| 发射 | 素材 Alpha、素材亮度、外部亮度图层；内部/边缘发射；持续发射与停止后自然消退 |
| 运动 | 初速、方向、连续散开；高级阻尼；序列帧内容拖尾；可缓存的光流运动继承 |
| 外观 | 细尘、亮点、星芒、短光丝；默认弱光晕；外观与运动方式独立组合 |
| 颜色 | 独立颜色图层、出生携色、统一颜色/渐变；至少 Normal 与 Add 的明确混合行为 |
| 动画 | 出现与消失预设及时间调整；闪烁开关、强度和频率；固定随机种子 |
| 质量 | 正确的 Alpha 合成与透明边缘；明确支持的位深、色彩空间和像素宽高比；至少提供可保留高光的 32 bpc 路径 |
| 预设 | 覆盖元素闪耀、粒子拖尾、持续逸散、背景氛围四个主要用途的成品预设库 |
| 性能 | 正确的缓存失效；预览质量控制；在目标机器上报告代表性场景的预览和渲染数据 |
| 烘焙 | 对指定时间范围生成可重新导入 AE 的透明图像序列；保留可编辑源效果 |
| 更新 | 开发模式资源重载；更新后的缓存刷新；原生插件的一键构建与安装流程 |

GPU 是优先研究和验证的实现方向，不是未经验证的性能承诺。只把已经实测的计算与绘制环节标为 GPU 加速。正式支持的操作系统、AE 版本、GPU 与位深需要有对应验证记录。

建议首发准备至少 16 个有明确行为或外观差异的预设，具体数量是开发建议，不是用户已经确认的硬性数字。单纯换颜色不计作不同的行为预设。

### 3.5 已确定但放在后续版本的能力

下列需求保留，不因 V1.0 聚焦二维而取消：

- 纵深开关、三维粒子位置与 AE 摄像机联动。
- 插件内部依据 AE 摄像机参数渲染景深。
- Crossphere Bokeh 配套颜色图与 Z 深度图输出。
- 沿途染色、贴图调色盘、更多图像通道到粒子属性的映射。
- 读取适配后的外部运动矢量通道。
- 用户自定义图层/预合成/文字粒子外观与克隆排列。
- 更复杂的影响器、力场、旋涡和局部控制。

正式决定进入这些模块时，应补充坐标定义、数据格式、性能预算和独立验收场景。

## 4. 面板结构

### 4.1 主面板原则

日常使用流程是“选择预设 → 指定必要来源 → 调疏密、大小和存活时间”。不要把内部算法名称、缓存格式或全部物理参数直接铺在第一屏。

0.5.0 沿用 v0.2 的 4 个主面板入口；源图层选择放在独立 Sources 组。预设可改变视觉默认值，但不能偷偷更换用户已经连接的图层。

| 主面板项目 | 含义 | 显示规则 |
| --- | --- | --- |
| Preset | 选择内置外观、动画与运动组合 | 始终显示 |
| Density | 每秒出生量，控制疏密 | 始终显示 |
| Size | 统一缩放外观尺寸，保留预设内的大小层次 | 始终显示 |
| Lifetime | 粒子存活时间，同时影响拖尾持续长度 | 始终显示 |

“密度”和“寿命”并非完全独立：持续发射时，存活数量大致随两者增加。面板应显示实际粒子数量或达到上限的状态，避免用户误以为密度滑块不生效。

0.5.0 使用 AE 原生分组控件和独立 ScriptUI 预设面板。未来的亮度、运动继承或节奏快捷入口需要证明能改善常用流程，不能无条件增加顶层参数。

### 4.2 来源组

来源组是常用工作流配置，不属于高级物理设置。默认尽量复用当前输入。

| 项目 | 默认行为 |
| --- | --- |
| 发射来源 | 当前输入素材 |
| 发射通道 | Alpha；可切换素材亮度或外部亮度图层 |
| 外部发射图层 | 仅选择外部亮度时显示 |
| 颜色来源 | 当前输入；可改为单色、渐变或独立颜色图层 |
| 运动参考 | 默认原始画面；仅启用运动继承时需要 |
| 显示原始素材 | 默认保留；用户可只输出透明粒子层 |

外部图层必须定义明确的时间与坐标对齐方式。预合成、图层变换、裁切、时间重映射和不同分辨率不得凭显示尺寸猜测取样位置。

### 4.3 折叠分组

Sources、Appearance、Animation、Advanced 默认折叠。阻尼不得提升到主面板，也不得因套用预设而自动展开。

| 当前分组 | 参数/能力 |
| --- | --- |
| Sources | 发射来源、发射通道、外部亮度图层、独立颜色图层、原图显示 |
| Appearance | 颗粒形状、内部混合、颜色模式、染色、光晕、不透明度 |
| Animation | 淡入、淡出、闪烁强度和频率 |
| Advanced → Motion | 初速、方向、散开、阻尼 |
| Advanced → Timing | 随机种子、预热、停止发射时间 |
| Advanced → Development | 重新读取当前预设资源 |

内部/边缘发射、阈值、反相、属性曲线、光流细节、计算质量、缓存与烘焙仍按版本范围逐步添加到适当分组；上表不是这些未来能力已经完成的声明。

### 4.4 预设面板

面板提供“内置预设”和“我的预设”两个入口，以及预设说明、应用、命名保存和刷新操作。首批内置项为元素闪耀、细尘拖尾、星芒拖尾、轻柔漂移、向外火花和背景浮尘。

用户预设保存当前帧的 17 项视觉/运动数值，不保存动画曲线。来源图层、颜色图层、外部遮罩、发射通道、种子、预热、停止时间、原图显示与原生 Preset 下拉保持目标效果原值。相同名称自动另存，保留旧文件。

应用前必须先检查所有目标参数；任一目标字段已有关键帧或表达式时，整次应用拒绝，不产生一半旧值一半新值的状态。此阶段不添加删除功能，不替用户删除预设文件。

## 5. 功能行为定义

### 5.1 发射与持续性

发射依据是概率或权重分布，不要求一个像素等于一个粒子。Alpha 或亮度较高的位置通常有更高出生概率；阈值与反相属于高级设置。

每次出生读取当时的发射图层。主体移动后，只有新粒子的出生位置变化；已经出生的粒子继续独立运动。停止发射不会立即删除已有粒子。保留源素材与只输出粒子必须是明确选项。

### 5.2 颜色

默认“出生携色”：使用出生时间、出生位置取样 RGB；颜色随后跟随该粒子。发射图层的灰度权重不应强制把粒子染成灰色。

原始图层含透明边缘时，需要正确处理预乘 Alpha，避免暗边和脏色。颜色管理、位深与内部叠加必须一致。高亮粒子不应默认硬裁成白色。

后续“沿途染色”按粒子的当前位置/当前时间取色；“贴图调色盘”提取配色后按稳定的粒子 ID 分配。两者不能与出生携色混用名称。

### 5.3 初速、惯性与阻尼

建议的语义为：

`出生速度 = 基础发射速度 + 运动继承比例 × 分析得到的画面速度`

运动继承是出生时的一次速度赋值。它不同于每一帧强行把老粒子吸附到主体，也不同于把整条拖尾随主体整体移动。

阻尼使用随时间连续衰减的定义。例如在不受其他力时，速度按 `v(t) = v0 × exp(-d × t)` 衰减；`d = 0` 表示不减速。具体单位可以封装为易理解的滑块，但底层结果不能依赖预览帧率。

出生速度、阻尼和寿命共同决定粒子的最终移动距离。阻尼只改变运动，不应直接改变颜色或闪烁节奏。

### 5.4 出现、闪烁与消失

三者独立组合：

- 出现：直接出现、透明度淡入、从小变大。
- 闪烁：关闭、轻微闪耀、明显闪耀、快速闪烁；强度和频率独立。
- 消失：透明度淡出、缩小、闪亮后消退。

出现与消失默认按粒子寿命比例控制；闪烁频率使用每秒次数。每个粒子具有稳定随机相位和适度频率差异，避免同闪，也避免逐帧重新随机造成噪点跳动。

透明度、大小、亮度必须可分别驱动。普通缩放消失不应把预设的星芒拉伸方向一并随机重置。

### 5.5 内容拖尾与光流

基础拖尾每帧读取主体分布，在当前位置产生粒子，旧粒子留在曾经经过的位置并消退。此模式不需要位置关键帧，也不需要光流。

光流模式比较相邻帧，得到二维位移，再按实际采样时间差换算为速度。所有新粒子共享该帧对的运动图，不为每颗粒子重复执行图像分析。

运动分析优先读取有可辨认纹理的画面。纯白遮罩、重复图案、遮挡、镜头切换及运动模糊可能产生不可信结果。低可信度区域应衰减继承量，不能随机给粒子巨大速度。首帧无前一帧时应有确定的零继承或明确回退规则。

此模式只估计画面 X/Y 运动，不承诺恢复真实三维 Z 向速度。外部运动矢量通道需要明确通道编码、单位、方向、坐标系、时间间隔与有效区域后才能适配。

### 5.6 纵深与景深：后续模块的固定方向

默认不开启纵深。开启后再读取 AE 摄像机，并明确插件内部坐标到摄像机坐标的变换。

内部景深由插件在粒子合成前依据摄像机参数处理；AE 不会自动为已经拍平的二维插件输出还原每颗粒子的深度。

外部 Crossphere Bokeh 模式输出未加内部景深的颜色图与配套深度图。深度应采用明确的摄像机空间定义，提供近远映射和反相约定；两份输出必须使用同一帧、同一随机种子、同一粒子状态。

单张深度图无法完整表达同一像素处多个半透明粒子的深度。复杂前后叠加优先使用内部景深，不引入手工深度分组工作流。

## 6. 缓存、烘焙和更新

### 6.1 分级缓存

| 缓存层 | 保存内容 | 修改哪些内容需要失效 |
| --- | --- | --- |
| 输入/分析 | 发射分布、运动分析结果等 | 来源图层、时间关系、空间对齐、分析设置变化 |
| 模拟 | 出生记录、速度、轨迹或检查点 | 发射量、初速、阻尼、寿命、运动继承、种子变化 |
| 外观/渲染 | 当前粒子最终图像 | 外观、颜色、闪烁、光晕、摄像机、景深变化 |

修改颜色或光晕不应重新分析光流。修改运动继承可以复用光流，但必须使对应模拟缓存失效。修改阻尼不能继续使用旧轨迹。缓存命中与失效应能诊断，不能以关闭全部缓存解决所有问题。

AE 可以非顺序请求帧，也可能并行渲染不同帧。不能只实现“从上一帧继续一步”的单一全局状态。必须采用确定性重建、历史出生求值、检查点或其他能处理任意时间访问的方法。

### 6.2 烘焙

首个烘焙流程面向指定工作区，把粒子效果输出为保留透明度的图像序列，重新导入并保留原始可编辑层。最终文件格式与位深必须与渲染能力相符。

未来内部景深模式烘焙已经完成景深的颜色结果；外部 Bokeh 模式烘焙清晰颜色和深度。若要避免 Crossphere Bokeh 本身的重复计算，需要再预渲染其最终合成结果。

模拟缓存只减少模拟，不能替代绘制或后续景深。首次烘焙仍然需要实际计算，不能承诺零成本。

### 6.3 开发热更新

- 预设、贴图、配色与动画曲线：设计为资源重读，不必重启 AE。
- 外置 GPU 计算/绘制代码：在参数与缓冲结构兼容时，尝试重新编译并安全切换；编译失败保留旧版本。
- 原生 C++ 主体、参数结构及底层接口：保留重新编译、安装、重启 AE 的可靠路径。

资源更新需要增加对应版本标识、使相关缓存失效并刷新画面。不能只改变磁盘文件却继续显示 AE 的旧缓存。已有参数、随机种子、来源连接应保留。

首个验证版优先把构建与安装过程固化；没有实际做出资源重载前，不把“覆盖插件文件”称作热更新。

## 7. 预设设计

预设由行为、外观、动画和配色共同组成。用户来源连接与预设内容分开保存。加载预设时，保留已经指定的素材、发射通道和颜色图层。

| 家族 | 代表方向 | 主要调整入口 |
| --- | --- | --- |
| 元素闪耀 | 克制细闪、轮廓星芒、柔和亮点、短促闪光 | 密度、大小、闪耀节奏 |
| 运动拖尾 | 彩尘、清晰碎光、星芒拖尾、短光丝 | 密度、保留时间、运动继承 |
| 持续逸散 | 向外散发、轻微上浮、侧向飘散、渐停散开 | 发射速度、寿命、密度 |
| 背景氛围 | 稀疏浮尘、缓慢亮点、局部装饰、轻微流动 | 密度、大小、亮度 |

预设需要在黑底、浅底、透明输出、文字、Logo 和运动序列帧上检查。不能只在某一张演示图上好看。弱光晕是默认审美方向，强光晕由特定预设或用户主动开启。

## 8. 测试与验收

### 8.1 核心验证场景

1. 静态带 Alpha 的文字持续发射；源文字不被消耗；关闭发射后老粒子自然消退。
2. 序列帧主体在画面中移动，AE 图层位置不打关键帧；粒子出生区域仍正确移动。
3. 外部灰度序列控制出生区域，原始彩色素材控制粒子颜色，两个通道不混淆。
4. 0 阻尼与高阻尼产生可辨认的运动距离差异；相同时间在不同采样步长下结果一致。
5. 运动继承 0%、100%、200% 有明确差异；只改变继承比例不重新做光流分析。
6. 关闭闪烁后保留出现/消失；光晕为 0 时颗粒与星芒仍然存在。
7. 固定种子下，同一帧重复渲染、反向拖动和跨帧跳转结果一致。
8. 保存、关闭、重开工程后，参数、种子、来源连接和效果保持一致。
9. 不同位深、透明边缘和内部混合模式无明显暗边或错误裁切；不支持的位深明确报告。
10. 修改阻尼、寿命、来源、颜色等设置分别触发正确的缓存失效范围。

### 8.2 性能记录

使用固定场景、固定随机种子和固定质量比较。记录机器型号、AE 版本与运行架构、分辨率、帧率、时间范围、粒子数、粒子屏幕尺寸、位深、混合方式、运动模糊/景深状态、冷缓存和热缓存耗时。

至少记录静态闪耀、连续逸散、内容拖尾三个场景；光流模式单独报告分析时间和后续预览时间。比较低、中、高密度，避免只用粒子数量描述性能。

目标是让常用二维装饰流程保持顺畅，具体帧率和粒子上限根据实测制定。不得在没有同场景比较的情况下宣称比 Particular 更快。

## 9. 公开构建与验证边界

当前构建目标为 macOS arm64，开发验证宿主为 AE 23.6。其他系统、架构、AE 版本与位深需要各自的验证记录。安装目录存在、成功编译或通过独立核心测试均不等同于实际宿主支持。

SDK 从 Adobe 官方单独获取，不进入本项目源码或公开制品。公开文档使用通用路径或相对路径，不记录开发者的个人目录、设备标识、账户或私有素材信息。

每个版本记录“已实现、已测试、未实现、已知限制”；公共使用说明记录可复现的场景和结论，原始本机日志、SDK 和测试产物保留在被忽略的本地目录。
